## 1. 현재 상태 요약

이미 있는 것:
- 아이패드 중심 작업 화면: 상단 도구 막대, 팝오버 패널, 크기/불투명도 사이드바, 하단 타임라인
- 벡터·래스터 브러시, 스머지, 지우개, 채우기, 선택(사각형/올가미), 베지어 노드 편집, 스크린톤, 선 흔들림
- 레이어(그룹, 마스크, 혼합 모드), HSV 색상과 스포이드, 팔레트
- 멀티 터치 제스처(핀치 확대·회전, 두/세 손가락 탭 실행 취소/다시 실행)
- 멀티트랙 타임라인: 레이어마다 트랙, 그림 길이(홀드), 재생, 벡터 어니언 스킨
- 레이어 움직임 키프레임(위치·회전·크기·불투명도, 이징)

비어 있는 핵심(코드 확인 결과):
- **작품 저장/불러오기 없음.** 새로고침하면 작업이 사라짐(팔레트만 localStorage 저장).
- **애니메이션 내보내기 없음.** 현재 프레임 PNG 한 장만 내보낼 수 있음.
- **Apple Pencil 전용 그리기 모드 없음.** 손가락도 그림을 그림. 실제 iPad 검증도 아직 없음.
- 실행 취소가 도구마다 따로 있고, 그림(클립)이 바뀌면 기록이 지워짐.
- 모든 저장이 PNG data URL이라 그림이 많아지면 메모리와 속도가 급격히 나빠질 위험.

## 2. 우선순위 원칙

1. **작업을 잃지 않는 것**이 새 기능보다 먼저다.
2. 결과물을 **밖으로 꺼낼 수 있어야** 앱으로서 의미가 있다.
3. 실제 iPad + Apple Pencil에서 **손에 붙는 느낌**을 확보한다.
4. 그다음에 드림의 대표 기능(오디오, 퍼포먼스 녹화, 클립 편집)을 넣는다.
5. 각 항목은 작은 PR로 나누고, 순수 모듈 + 테스트를 먼저 만든다.

## 4. 추천 진행 순서 (마일스톤)

1. **M1 — 잃지 않는 앱** (P0 #1, #7, #4, #5): 저장 형식 → 자동 저장/복원 → 펜 전용 모드 → 실기기 검증
2. **M2 — 꺼낼 수 있는 앱** (P0 #3, #2): 내보내기, 갤러리
3. **M3 — 믿을 수 있는 편집** (P0 #6, P1 #8): 통합 실행 취소, 클립 편집
4. **M4 — 드림다운 연출** (P1 #9–#13): 플립북, 어니언, 오디오, 퍼포먼스, 키프레임 편집
5. **M5 — 도구 완성도** (P1 #14–15, P2)

M1이 끝나기 전에는 새 연출 기능을 쌓지 않는 것을 권장한다. 저장 형식이 정해지기 전에 기능을 늘리면 나중에 마이그레이션 비용이 커진다.

## 5. 설계 메모 (M1 착수 전 합의 필요)

- **문서 스키마:** `{ version, canvas: {width, height}, fps, layers: [{id, name, …, motionTrack}], groups, tracks: {[id]: {clips: [{id, hold, imageKey, transformCel, strokes}]}}, palette }`. 이미지는 IndexedDB의 별도 store에 `imageKey`로 저장.
- **자동 저장 단위:** 변경된 클립만 다시 인코딩(`OffscreenCanvas.convertToBlob`), 문서 JSON은 디바운스 저장.
- **실행 취소:** 픽셀 변경은 바운딩 박스 영역만 저장하는 패치 방식, 기록 상한(예: 64MB)을 두고 오래된 것부터 제거.
- **내보내기:** WebCodecs가 있으면 MP4/WebM 직접 인코딩, 없으면 MediaRecorder 또는 PNG 시퀀스로 대체. iPad Safari 지원 범위를 먼저 확인.
- **역할 분담:** 기획·설계·구현·테스트는 Claude, 사용자 문서·문구 제안·QA 체크리스트·조사는 ChatGPT (`docs/PROJECT_GUIDE.md` 6장).

## 6. 위험 요소

- iPad Safari의 메모리 한도: 고해상도 레이어 × 많은 클립에서 탭이 강제 종료될 수 있음 → #7과 성능 계측을 먼저.
