# 실시간 필압 벡터 스트로크 개선 작업 지시서

> 대상 프로젝트: FRAME Studio  
> 목적: Apple Pencil/스타일러스 입력 중에도 필압이 반영된 벡터 선을 즉시 자연스럽게 표시하고, 펜을 뗀 뒤 최종 결과와 위치·굵기·형태가 일치하도록 개선한다.

## 1. 현재 구현 확인 사항

작업 시작 전 아래 내용을 기준으로 실제 코드와 테스트를 다시 확인한다.

- 래스터 브러시는 `apps/web/src/brush/brush-engine.js`에서 `perfect-freehand`로 가변 굵기 외곽선을 생성한다.
- 래스터 입력에는 필압 정규화, coalesced pointer samples, 프레임 단위 미리보기 스케줄러, 스트로크 안정화가 이미 존재한다.
- 벡터 선은 `apps/web/src/line/line-engine.js`의 독립 스트로크 객체이며, 각 점에 `x`, `y`, `pressure`를 저장한다.
- `apps/web/src/line/vector-rendering.js`는 경로를 따라 압력을 보간하고 구간별 굵기를 계산한다.
- 따라서 필압 자체를 처음부터 추가하는 작업이 아니라, **벡터 입력 중 샘플 수집 → 임시 렌더링 → 최종 확정 과정의 연결과 일관성을 검증·개선하는 작업**이다.
- 래스터 브러시와 벡터 선의 렌더링 경로를 혼동하거나, 벡터선을 래스터로 바꾸는 방식으로 문제를 우회하지 않는다.

## 2. 우선 조사할 코드 경로

다음 흐름을 실제 코드에서 추적하고, 각 단계의 데이터와 호출 시점을 기록한다.

1. PointerEvent 수신 및 펜/손가락 구분
2. pressure, timestamp, client 좌표 수집
3. coalesced samples 처리 여부와 누락·중복 샘플 여부
4. 화면 좌표를 문서/캔버스 좌표로 변환하는 과정
5. 벡터 스트로크 임시 데이터 갱신
6. PixiJS 실시간 프리뷰 렌더링
7. pointerup 시 최종 벡터 스트로크 생성·확정
8. 확정 직후 다시 렌더링될 때 프리뷰와 결과가 달라지는지 확인
9. Undo/redo, 프레임 클립 저장·복원, 확대/축소·회전 및 화면 이동 후 동일하게 동작하는지 확인

관련 파일:
- `apps/web/src/main.js`
- `apps/web/src/renderer.js`
- `apps/web/src/line/line-engine.js`
- `apps/web/src/line/vector-rendering.js`
- `apps/web/src/line/vector-brush.js`
- `apps/web/src/viewport/coordinates.js`
- `apps/web/src/brush/brush-engine.js` (기존 입력/스케줄링 구현 참고)

## 3. 요구 동작

### A. 실시간 필압 반영
- 펜이 움직이는 동안 입력 압력 변화가 선 굵기에 지연 없이 반영되어야 한다.
- 압력 샘플을 임의로 평균내어 중요한 변화가 사라지지 않도록 한다.
- 입력이 드문 구간은 위치와 압력을 자연스럽게 보간하되, 실제 샘플을 덮어쓰지 않는다.
- 마우스·손가락 입력은 현재의 대체 압력 정책을 유지하고 펜 입력과 구분한다.

### B. 실시간 벡터 프리뷰
- 매 입력 이벤트마다 무거운 전체 렌더링을 반복하지 말고, 프레임 단위로 갱신을 묶는다.
- 프리뷰는 현재까지 수집된 벡터 점과 압력 데이터를 사용한다.
- 선을 그리는 중에도 곡선과 가변 굵기가 자연스럽게 표시되어야 한다.
- 프리뷰 전용 데이터와 문서에 확정된 벡터 객체를 분리한다.
- 프리뷰가 기존 선, 선택 상태, 레이어 및 애니메이션 프레임을 오염시키지 않도록 한다.

### C. 프리뷰와 최종 결과의 일치
- 프리뷰와 최종 확정 렌더링이 같은 좌표 변환, 압력 보간, 브러시 프로파일 및 굵기 계산 규칙을 사용하도록 공통 계산 경로를 최대한 공유한다.
- pointerup 시 선이 튀거나 위치·굵기·곡률이 갑자기 바뀌지 않아야 한다.
- 마지막 입력 샘플이 누락되거나 중복되어 끝부분이 꺾이지 않아야 한다.
- 필요하면 진행 중 상태와 완료 상태의 차이를 명시적으로 관리하되, 완료 처리만으로 전체 선 모양이 급격히 변하지 않게 한다.

### D. 지연 최소화
- `getCoalescedEvents()` 지원 여부를 확인하고 벡터 입력에도 올바르게 적용한다.
- `getPredictedEvents()`는 브라우저·기기 지원 여부와 실제 효용을 측정한 뒤, 예측 좌표를 임시 표시 전용으로 제한해 검토한다. 예측 좌표를 저장되는 벡터 데이터에 섞지 않는다.
- requestAnimationFrame 기반 프리뷰 갱신을 검토하고, 취소·종료·pointercancel 시 예약된 프레임과 임시 그래픽을 정리한다.
- 프레임마다 전체 벡터 문서나 모든 레이어를 불필요하게 다시 그리지 않는다.

## 4. 벡터 데이터 및 편집성 보존

- 기존 독립 벡터 스트로크 객체와 안정적인 ID를 유지한다.
- 각 점의 압력 데이터를 저장·복제·이동·스무딩·노드 삽입/삭제·프레임 저장/복원 과정에서 보존한다.
- 확대해도 선의 형태가 깨지지 않고 기존 벡터 편집 기능과 호환되어야 한다.
- 일반 드로잉 과정에서 벡터선을 래스터화하지 않는다.
- 압력 기반 가변 굵기가 히트 테스트, 선택, 이동, 내보내기 결과와 가능한 한 일치하도록 한다.
- 기존 저장 포맷과 호환되지 않는 변경이 필요하면 마이그레이션과 하위 호환 계획을 먼저 제시한다.

## 5. 오픈소스 검토 원칙

- **perfect-freehand (MIT)**: 이미 래스터 브러시에 통합되어 있다. 벡터에서도 외곽 형상 생성에 활용할 수 있는지 검토하되, 기존 편집 가능한 중심선·노드 구조를 잃지 않는 어댑터 방식인지 확인한다.
- **Quickdraw (MIT)**: 펜/손가락 분리, 입력 처리와 스트로크 워크플로를 참고한다. 현재 PixiJS 구조에 통째로 넣지 않는다.
- **Drawfinity**: 렌더링 및 성능 구조를 참고한다. 실제 유지보수 상태·라이선스·기술 호환성을 확인하기 전에는 의존성으로 추가하지 않는다.
- 라이브러리를 추가하기 전 저장소 활동, 정확한 라이선스, 번들 크기, 브라우저 호환성, 기존 구현과의 중복을 확인한다.
- 참고한 코드와 실제로 도입한 코드를 구분해 `docs/open-source.md`에 기록한다.

## 6. 검증 시나리오

- 약한 압력에서 강한 압력으로 천천히 바꾸기
- 강한 압력에서 약한 압력으로 빠르게 바꾸기
- 일정한 압력으로 직선·곡선 그리기
- 빠른 스트로크와 느린 스트로크 비교
- 짧은 선, 긴 선, 급격한 방향 전환
- 그리는 중 확대·축소·회전·이동
- 두 손가락 제스처로 스트로크 취소
- pointercancel, 창 포커스 변경, 프레임 전환
- 선 확정 직후 프리뷰/최종 결과의 위치와 굵기 비교
- Undo/redo 및 저장 후 재실행·프레임 복원
- 마우스와 손가락 입력의 기존 동작 회귀 확인

가능하면 자동 테스트로 압력 보간, 샘플 보존, 프리뷰/커밋 공통 geometry 계산을 검증하고, 브라우저에서 실제 드로잉 시나리오를 확인한다. 물리 iPad와 Apple Pencil 테스트는 별도로 표시하며, 테스트하지 않은 항목을 완료로 보고하지 않는다.

## 7. 완료 기준

- 선을 긋는 순간부터 필압에 따른 굵기 변화가 화면에 자연스럽게 보인다.
- 프리뷰와 확정 결과 사이에 눈에 띄는 점프·위치 이동·굵기 변화가 없다.
- 빠른 입력에서도 선이 끊기거나 압력 변화가 크게 누락되지 않는다.
- 벡터 점·압력·ID·편집 기능과 프레임 저장이 보존된다.
- pointercancel과 제스처 취소 시 미완성 스트로크가 문서에 남지 않는다.
- `npm test`와 `npm run build` 결과 및 브라우저 검증 결과를 보고한다.
- 실제 iPad 테스트를 수행하지 않았다면 그 사실을 명확히 기록한다.

## 구현 우선순위

1. 현재 벡터 입력/프리뷰/커밋 경로의 문제 재현 및 원인 분석
2. 입력 샘플과 압력 데이터가 프리뷰까지 전달되는지 검증
3. 프리뷰와 커밋의 geometry 계산 공유
4. 프레임 단위 렌더링 및 불필요한 재렌더링 제거
5. 자동 테스트와 브라우저 회귀 테스트
6. 실제 iPad/Apple Pencil 검증

**중요:** 이 작업의 핵심은 단순히 필압 기능을 추가하는 것이 아니라, 사용자가 펜을 움직이는 바로 그 순간 최종 벡터선과 동일한 품질의 선을 보게 만드는 것이다.
